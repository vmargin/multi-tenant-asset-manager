# AssetHub production user-test log

- **Date:** 8 October 2026 (Asia/Manila)
- **Application:** [multi-tenant-asset-manager.vercel.app](https://multi-tenant-asset-manager.vercel.app/)
- **Test type:** Browser-driven user simulation against the live production site

## Result

The main account, inventory, checkout, return, location, maintenance, audit, report, and workspace flows work for the synthetic accounts and records tested. I recorded eight user-facing defects below. The most disruptive is selecting the workspace that is already active: the app clears the loaded workspace and remains on a loading screen until the user signs out and back in.

No application source or deployment was changed, and no commit or push was made. The UI was tested in Playwright at desktop and at 390px and 320px widths. All test identities and records were synthetic. No invitation emails were sent and no physical labels were printed.

## Confirmed defects

| ID | Priority | Page | Expected | Actual |
|---|---|---|---|---|
| F1 | P1 | Organization switcher | Selecting the already-active organization should keep the current workspace open. | In the QA workspace, selecting its current organization clears the workspace and leaves “Loading your workspace…” indefinitely. Reloading did not recover it; signing out and signing in did. The normal switch between two different demo organizations worked. Both workspace API calls returned 200 during the stuck state. |
| F2 | P2 | Retired asset detail | A retired asset should not offer a maintenance action that the server disallows. | “Report an issue” remains visible. Submitting it returns HTTP 409 with “Retired assets cannot receive maintenance requests”; no request is created. Reproduced on the QA Monitor and the demo Epson EcoTank Pro. See [retired asset evidence](screenshots/qa-retired-asset-report-issue.png). |
| F3 | P2 | Notifications → Assignments | The filter should include checkouts and returns shown in All. | In All, checked-out and returned assets appeared. Assignments showed an empty state in the same workspace, while a transfer event in the QA workspace did appear. See [empty Assignments filter](screenshots/qa-assignments-filter-empty.png). |
| F4 | P2 | Dashboard → Recent activity | A row presented as a button with a chevron should open a relevant record or otherwise be presented as noninteractive. | Rows without an associated asset, including audit and membership events, did nothing when clicked. The route did not change. |
| F5 | P2 | Global search | Opening search from its toolbar button should place the cursor in the search field. | After clicking the toolbar button and waiting 250 ms, focus remained on “Close.” Ctrl+K did focus the search field. Escape closed the dialog, but focus then fell to the document body. |
| F6 | P2 | Assets status filter | “All statuses” should include every status, including Retired. | The default shows active assets only (22 in the demo). Retired assets appear only after selecting Retired (1 in the demo). |
| F7 | P2 | Asset CSV export | The same date column should use a consistent format in each export. | “Export” writes dates such as “Oct 1, 2026”; “Export selected” writes ISO timestamps such as “2026-10-01T00:00:00.000Z,” under the same Purchase date header. |
| F8 | P3 | Browser tab | The title should identify the current signed-in product page. | The tab continues to say “AssetHub · Workspace access” after sign-in and while navigating authenticated pages. |

## Test data and current state

- QA records stayed inside the synthetic QA workspace: two locations, two categories, QA Laptop available, QA Monitor retired, resolved maintenance requests, two completed audits, and three active QA users (Owner, Manager, Member).
- The demo tenant retained its seeded inventory. A synthetic pending Manager invitation remains in Acme Corp. Its email is a reserved test address; the link was not sent to anyone.
- The QA organization description was restored to blank and currency to PHP. The QA Storage note was restored. The synthetic demo member’s original Member role was restored.
- The demo browser’s notification-read preference was set to zero unread at the end of the run. The browser was left signed in to the demo dashboard in light mode.
- The invitation link and passwords are intentionally omitted from this report.

## Limits

No invitation email delivery, physical printing, password recovery, concurrent-user race, penetration test, or production load test was attempted. The recorded 400/409 responses were expected rejections during negative QA checks; the browser console showed no warnings.

## Follow-up remediation

**Date:** 8 October 2026

| ID | Change |
|---|---|
| F1 | Selecting the currently loaded organization now closes the switcher without clearing workspace state or starting a redundant reload. |
| F2 | Retired asset details no longer show “Report an issue,” matching the API’s existing lifecycle rule. |
| F3 | Assignments matching now recognizes checked-out, checked-in, returned, transferred, and assigned activity labels, including underscore-separated action names. |
| F4 | Recent-activity rows without an asset are now static rows without a chevron; rows with an asset remain buttons that open the asset. |
| F5 | Search and organization dialogs focus their search field after opening and return focus to the opener after closing. |
| F6 | The unfiltered asset list now includes retired assets; selecting a specific status still filters to that status. |
| F7 | Full and selected asset exports now share the same date and related-field formatter. |
| F8 | The document title now follows the signed-in page and returns to “AssetHub · Workspace access” on public access. |
